## 4. 보완점 (분석에서 나온 것, 중요한 순서)

### 🔴 제출 전 꼭
1. **두 번째 매장** — 영상 16번·'범용성' 주장에 필요. **카페가 아닌 업종**(분식집 등)을 추천: `HARD_WORDS`·`must` 를 거의 안 고치고도 검사를 통과하면 "메뉴 파일만 있으면" 주장의 근거가 됨
2. **사용자 테스트 숫자** — 영상 17번 (기존 키오스크 vs 내 방식 QR: 주문 시간·실수 횟수)
3. **배포 URL** — 공모전 제출용. 위 "배포 시 주의" 참고

### 🟡 AI 문구 품질 (`docs/samples/AI_변환_샘플.md` 에서 발견, 담당: 민희)
검사 8개는 통과했지만 화면·/lab 에 크게 보이면 감점 요인:
- 같은 말 반복: 레몬에이드 "탄산이 들어 있는 음료, **탄산이 들어 있어요**" → 반복 문구 검사 추가 또는 지시문 보완
- 정보가 사라짐: 바스크 치즈케이크 "한 조각이에요" (무엇인지 없음)
- 어색함: 아메리카노 "물과 함께 진한 커피예요"
- 규칙 위반: 초코라떼 "카페인이 있어요" — 지시문은 must 에 있을 때만 카페인 안내
- '쉬운 말 끔' 결과도 많이 바뀌어서 켬/끔 차이가 잘 안 보임

### 🟡 범용성 주장의 빈틈
- `HARD_WORDS`(ai_rules.py)와 메뉴별 `must` 를 **사람이 카페에 맞춰 손으로** 씀 → "어느 키오스크든"과 어긋남.
  두 번째 매장에서 손이 많이 가면 보고서에 "다음 단계: 매장 등록 시 AI 가 must 후보 추천"으로 정리
- AI 가 바꾸는 건 **문구·묶음뿐**, 배치·단계는 CSS 고정. 질의 답변서 2번("버튼 배치와 설명 단계")을 의식하면
  보고서에 "문구·구조는 AI, 크기·대비는 규칙 기반 — 검사 가능한 범위만 AI 에 맡김"으로 **의도된 설계**라고 쓰기

### 🟡 측정 신뢰도
- 매장 1곳 · 30회뿐. 아주 큰 글씨는 1회 통과 1/10, 다시 시키느라 12~20초
- 보고서에는 숫자 3개를 **나눠서**: 1회 통과율 70% / 최종 성공률 100% / AI 실패해도 원본으로 주문 가능 100%
- 매장 2곳 × 5회 이상으로 다시 측정 권장 (`check_transform.py 5 save`)

### ⚪ 작은 것
- 창구 번호 4자리라 추측 가능 — 시제품이라 괜찮지만 보고서 '향후 과제'에 한 줄
- `@app.on_event("startup")` 은 FastAPI 에서 곧 없어질 방식 — 급하지 않음

## 5. 커밋 메시지 예시 (한국어, AGENTS.md 4)
```
폰 주문 흐름 완성: 옵션(한 화면 한 질문) → 주문 목록 → 목업 결제 → 완료

- 옵션 질문·선택지는 AI 문구(question/label), 주문에는 옵션 ID 만 보냄
- 주문 목록은 키오스크 창구별로 보관, 금액은 서버 재계산 값을 표시
- 키오스크 QR 주소 글자(내부 IP)는 ?debug 일 때만 표시
- 서버: ALLOW_FRESH=0 이면 fresh 무시, frontend/dist 있으면 화면도 서빙
```
